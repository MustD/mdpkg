# `mdpkg` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mdpkg`, an open-source Rust CLI tool (with AUR `PKGBUILD`) for declarative multi-host package management, validation, lifecycle hooks, and single-password system updates on Manjaro Linux using human- and AI-editable Markdown checklists.

**Architecture:** A modular Rust library and CLI (`src/lib.rs` + `src/main.rs`) built around a lossless line-oriented Markdown AST (`markdown`), a pure state reconciliation engine (`reconcile`), a filesystem hook runner (`hooks`), an abstracted package-manager backend (`sources` + `privilege`), and a `clap` CLI (`cli` + `commands`) with rich agent-oriented help. External system calls (`pacman`, `pamac`, `npm`, `sudo`) sit behind a `SystemBackend` trait so all sync, hook, and update workflows are deterministically unit- and integration-tested.

**Tech Stack:** Rust (2021 edition, MSRV 1.75+), `clap` v4 (derive), `serde` + `serde_json` + `toml`, `regex`, `dialoguer`, `anyhow`, `thiserror`, `tempfile` (dev-dependency).

**Spec:** `docs/superpowers/specs/2026-10-20-mdpkg-design.md`

## Global Constraints

- License: MIT (`LICENSE` file in repo root and `license = "MIT"` in `Cargo.toml`).
- Package source prefixes in Markdown: omitted or `m:` (`manjaro:`/`repo:`) → `PackageSource::Repo`; `a:` (`aur:` or legacy `Ⓐ`) → `PackageSource::Aur` (normalized to `a:` when rendered); `n:` (`npm:`) → `PackageSource::Npm`; any other `<prefix>:` is a syntax validation error.
- Inspection commands (`mdpkg check`, `mdpkg status`, `mdpkg validate`, `mdpkg list`, `mdpkg sync --dry-run`) are strictly read-only and never write `<hostname>.md` to disk.
- `mdpkg` never touches or uninstalls system packages that are not listed in `packages.md` / `<hostname>.md`.
- Normal `mdpkg sync` skips already-installed AUR packages unless `--force-aur` is passed.
- Hooks execute as the normal invoking user with `MDPKG_PACKAGE`, `MDPKG_SOURCE`, `MDPKG_STAGE`, `MDPKG_HOST`, and `MDPKG_DATA_DIR` set in the environment.

## Review Focus

1. **Hyphen and em-dash description separators + legacy `Ⓐ` in existing `packages.md`:** Existing real-world items use both ` — ` and ` - ` (e.g., `` - [ ] `dpkg` - debian package management ``) and `Ⓐ` without a space before the backtick (`` - [x] Ⓐ`google-chrome` — desc ``); parser must accept `—`, `--`, and `-` separators and normalize `Ⓐ` to `a:`. (Tested in Task 1)
2. **Unchecked category `### [ ]` preserves child `- [x]` checkboxes on disk:** When a category is `### [ ]` in `<hostname>.md`, its child `- [x]` items must evaluate as effectively disabled (queued for removal if installed on the system) while still rendering as `- [x]` in `<hostname>.md` so re-checking the category restores the selection. (Tested in Task 2)
3. **Google Drive stripped executable bits on hooks:** Hook files in synced directories may lack `chmod +x`; `.sh` and `.py` hooks must still execute via `bash` / `python3`, whereas extensionless non-executable hook files must be flagged by `validate_hooks`. (Tested in Task 3)
4. **`preInstall` hook failure isolates only the failing package:** If `foo_preInstall.sh` exits non-zero during a sync that also installs `bar`, `foo` is skipped from installation while `bar` still installs, and `sync` returns a non-zero status. (Tested in Task 4)
5. **Missing `npm` binary on a fresh Manjaro machine:** When `npm` is not installed, querying global npm packages returns an empty set and `mdpkg update` skips `sudo npm update -g` with a message rather than failing. (Tested in Task 4)

    #[test]
    fn hooks_init_creates_ai_readme_and_handles_non_executable_sh_and_orphan_validation() {
        let dir = tempdir().unwrap();
        let hooks_dir = dir.path().join("hooks");
        let readme = init_hooks_dir(&hooks_dir).unwrap();
        let readme_text = fs::read_to_string(&readme).unwrap();
        assert!(readme_text.contains("_preInstall"));
        assert!(readme_text.contains("docker_postInstall.sh"));
        assert!(readme_text.contains("ripgrep"));

        fs::write(&sh_hook, "#!/usr/bin/env bash\necho $MDPKG_PACKAGE > \"$MDPKG_DATA_DIR/hook_ran.txt\"\n").unwrap();

        // Extensionless non-executable hook -> should be flagged by validate_hooks
        let bad_hook = hooks_dir.join("git_preInstall");
        fs::write(&bad_hook, "echo hi").unwrap();

        // Orphan hook -> package not in catalog

        fs::write(&orphan_hook, "echo orphan").unwrap();

        let (prog, args) = resolve_hook_invocation(rg_hook).unwrap();
        assert_eq!(prog, "bash");
        assert_eq!(args, vec![sh_hook.to_string_lossy().to_string()]);

        let item = PackageItem {
            checked: true,
            source: PackageSource::Repo,
            explicit_m_prefix: false,
            name: "ripgrep".into(),
            description: "search".into(),
            line_no: 1,
        };
        run_hook(rg_hook, &item, "testhost", dir.path()).unwrap();
        assert_eq!(fs::read_to_string(dir.path().join("hook_ran.txt")).unwrap().trim(), "ripgrep");

        let known = HashSet::from(["ripgrep".to_string(), "git".to_string()]);
        let issues = validate_hooks(&hooks_dir, &known).unwrap();
        assert_eq!(issues.len(), 2); // bad_hook (not executable & no .sh/.py) + orphan_hook
    }
}
