# `mdpkg` v0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the 5 explicit package sources (`m:`, `a:`, `d:`, `n:`, `c:`), package-grouped hook directories (`hooks/<pkg>/<stage>`), custom script package scaffolding & updates, interactive section/category selection in `mdpkg add` (removing `--section` and `--category`), `mdpkg update --ignore <pkg>` with failure hints, direct `apt` execution, and Docker integration tests on Ubuntu and Manjaro/Arch.

**Architecture:** Extend `PackageSource` with `Apt` (`d:`) and `Custom` (`c:`), and extend `HookStage` with `Install`, `Remove`, and `Update`. Refactor `src/hooks.rs` to discover and validate per-package directories `hooks/<pkg>/<stage>[.sh|.py]` and scaffold `install.sh` / `remove.sh` templates. Update `SystemBackend` in `src/sources.rs` to handle `apt` (`d:`), custom script installation/removal/updates (`c:`) with per-host custom state tracking in `<data_dir>/.mdpkg/installed_custom_<host>.json`, and `--ignore` package lists during `mdpkg update`. Add Docker test suites under `tests/docker/`.

**Tech Stack:** Rust 2021 (1.75+), `clap` 4.5, `dialoguer` 0.11, `serde` / `serde_json`, `regex`, Docker (`ubuntu:24.04`, `manjarolinux/base` / `archlinux:latest`).

**Spec:** `docs/superpowers/specs/2026-11-19-mdpkg-v04-design.md`

## Global Constraints

- Explicit 5-source prefixes in Markdown and CLI:
  - `m:` (or unprefixed default) — Manjaro repositories (`PackageSource::Repo`)
  - `a:` (or legacy `Ⓐ`) — AUR (`PackageSource::Aur`)
  - `d:` (or `apt:`) — APT for Ubuntu / Debian (`PackageSource::Apt`)
  - `n:` (or `npm:`) — Global npm (`PackageSource::Npm`)
  - `c:` (or `custom:`) — Custom script (`PackageSource::Custom`)
- Use the `apt` CLI command (`sudo apt update`, `sudo DEBIAN_FRONTEND=noninteractive apt install`, `sudo DEBIAN_FRONTEND=noninteractive apt remove`, `sudo DEBIAN_FRONTEND=noninteractive apt upgrade`, `sudo DEBIAN_FRONTEND=noninteractive apt autoremove`) instead of `apt-get`.
- Remove `--section` and `--category` CLI flags from `mdpkg add`.
- Switch completely from flat `hooks/<pkg>_<stage>.sh` to grouped `hooks/<pkg>/<stage>[.sh|.py]`.
- When adding a package with source `c` (`Custom`), create `hooks/<pkg>/install.sh` and `hooks/<pkg>/remove.sh` stub templates and prompt the user to fill them in without immediately running the empty script.
- When `mdpkg update` fails, append a tip suggesting `mdpkg update --ignore <package_name>`.

## Review Focus

- Top-level files left in `hooks/<file>.sh` (flat legacy hooks) must be flagged by `validate_hooks` with a clear message directing to `hooks/<pkg>/<stage>.sh`.
- Newly scaffolded `hooks/<pkg>/install.sh` and `remove.sh` contain only comments (`# TODO:`); `is_stub_script` must detect scripts with no executable statements so `mdpkg check` and `mdpkg sync` reject unedited stubs instead of silently marking the custom package installed.
- Running `PrivilegeSession::acquire()` inside a root Docker container (`geteuid() == 0`) or on Ubuntu where `/etc/polkit-1/rules.d` is absent must not fail or require Polkit.
- `mdpkg update --ignore foo,bar` or `--ignore foo --ignore bar` must skip `foo` and `bar` across `pamac update`, `apt upgrade` (via `apt-mark hold`/`unhold`), and custom `c:` package update scripts.
- Reconciling a host file with `d:` and `c:` packages must check `InstalledPackages.apt` and `InstalledPackages.custom` respectively without cross-polluting `repo_and_aur`.

fn discovers_grouped_hooks_and_flags_flat_files_orphans_and_stubs() {
    let dir = tempdir().unwrap();
    let hooks_dir = dir.path().join("hooks");
    init_hooks_dir(&hooks_dir).unwrap();

    // Valid grouped hook: hooks/ripgrep/postInstall.sh
    let rg_dir = hooks_dir.join("ripgrep");
    fs::create_dir_all(&rg_dir).unwrap();
    fs::write(
        rg_dir.join("postInstall.sh"),
        "#!/usr/bin/env bash\necho $MDPKG_PACKAGE > \"$MDPKG_DATA_DIR/hook_ran.txt\"\n",
    )
    .unwrap();

    // Scaffold custom package scripts for rustup
    let (inst_path, rem_path) = scaffold_custom_package_scripts(&hooks_dir, "rustup").unwrap();
    assert!(inst_path.exists());
    assert!(rem_path.exists());
    assert!(is_stub_script(&inst_path).unwrap());

    // Flat file at top-level hooks/ must be flagged as invalid
    fs::write(hooks_dir.join("legacy_postInstall.sh"), "echo old\n").unwrap();

    let hooks = discover_hooks(&hooks_dir).unwrap();
    assert!(hooks.iter().any(|h| h.package == "ripgrep" && h.stage == HookStage::PostInstall));
    assert!(hooks.iter().any(|h| h.package == "rustup" && h.stage == HookStage::Install));
    assert!(hooks.iter().any(|h| h.package == "rustup" && h.stage == HookStage::Remove));

    let catalog_items = vec![
        PackageItem {
            checked: true,
            source: PackageSource::Repo,
            explicit_m_prefix: false,
            name: "ripgrep".into(),
            description: "".into(),
            line_no: 1,
        },
        PackageItem {
            checked: true,
            source: PackageSource::Custom,
            explicit_m_prefix: false,
            name: "rustup".into(),
            description: "".into(),
            line_no: 2,
        },
    ];

    let issues = validate_hooks(&hooks_dir, &catalog_items).unwrap();
    // 1 issue for legacy_postInstall.sh at root + 2 issues for unedited stub install.sh and remove.sh
    assert_eq!(issues.len(), 3, "Expected 3 issues, got: {:?}", issues);

    // Once user fills in install.sh and remove.sh, stub issues disappear
    fs::write(&inst_path, "#!/usr/bin/env bash\ncurl -fsSL https://sh.rustup.rs | sh -s -- -y\n").unwrap();
    fs::write(&rem_path, "#!/usr/bin/env bash\nrustup self uninstall -y\n").unwrap();
    fs::remove_file(hooks_dir.join("legacy_postInstall.sh")).unwrap();

    assert!(!is_stub_script(&inst_path).unwrap());
    let clean_issues = validate_hooks(&hooks_dir, &catalog_items).unwrap();
    assert!(clean_issues.is_empty(), "Expected no issues, got: {:?}", clean_issues);
